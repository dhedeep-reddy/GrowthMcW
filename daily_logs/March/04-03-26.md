# date: 04-03-2026

Today I studied some important concepts related to computer architecture and performance analysis. I started with pipelining and instruction-level parallelism from Algorithmica. In this I learned how modern CPUs improve performance by executing multiple instructions in parallel using pipelines. I understood that an instruction does not execute all at once, but goes through several stages such as fetch, decode, execute, memory access, and write-back. While one instruction is in the execute stage, another instruction can already be in the decode stage, which increases CPU utilization. I also learned about instruction-level parallelism (ILP) and how processors try to run independent instructions at the same time to improve throughput.

After that I studied about cache memory and the memory hierarchy including RAM and CPU caches. I understood why caches are needed and how accessing RAM is much slower compared to accessing data from the CPU cache. I learned about different cache levels such as L1, L2, and L3 cache, and how the CPU stores frequently used data in cache to reduce memory access latency. I also understood the concept of cache locality, including temporal locality and spatial locality, and how writing programs with good data access patterns can improve performance.

Next I went through the basics of profiling, mainly from the CppCon talk by Mathieu Ropert. From this I understood what profiling means and why it is important for performance optimization. Profiling helps in identifying which parts of a program consume the most time or CPU resources so that optimization efforts can be focused on those sections instead of guessing. I also understood that performance problems are often related to CPU usage, memory access, cache misses, or inefficient algorithms.

Finally, I studied profiler tools, especially the Linux perf tool. I learned that perf is used to analyze program performance using hardware performance counters provided by the CPU. It can measure things such as CPU cycles, instructions executed, cache misses, and branch mispredictions. I explored how perf can be used to record and analyze program execution and understand where time is being spent inside the program. This helped me understand how developers diagnose performance bottlenecks in real applications.
