## Daily Progress Report – CUDA Convolution Optimization

Today I worked on implementing and optimizing 2D convolution using CUDA and analyzed the performance of different kernel versions using NVIDIA Nsight Compute. The main goal was to understand how different CUDA optimization techniques affect performance, memory usage, and GPU utilization.

I started with a naive convolution implementation where each thread computed one output pixel and accessed global memory directly for all the convolution operations. After profiling this kernel, I observed that the execution time was the highest among all implementations. The profiler showed moderate SM utilization but the performance was limited due to frequent global memory accesses and memory latency. This helped me understand how expensive global memory access is and why memory optimization is important in CUDA.

Then I moved to shared memory tiling. In this version, each block loads a tile of the image into shared memory including the halo regions, and the convolution is performed using shared memory instead of repeatedly accessing global memory. After profiling, I observed that the execution time decreased and achieved occupancy increased compared to the naive version. This showed that shared memory significantly reduces global memory traffic and improves performance.

After that, I implemented register blocking with tiling, where each thread computes multiple output pixels instead of just one. This increases the amount of computation per thread and improves arithmetic intensity. Profiling results showed a significant improvement in execution time and SM utilization. Memory throughput and L2 cache throughput also increased, indicating better memory access patterns and improved GPU utilization.

Next, I removed boundary checks by padding the input image beforehand. This allowed the kernel to avoid conditional checks inside the convolution loop. I also applied loop unrolling to reduce loop overhead and improve instruction-level parallelism. The profiler showed that execution time reduced further and memory throughput increased. Removing boundary checks helped in reducing branch divergence and improved overall performance.

I then implemented double buffering in shared memory to overlap memory loading and computation. The idea was to load the next tile while computing the current tile. However, after profiling, I observed that the performance improvement was not very significant compared to the previous kernel. The shared memory usage increased due to double buffering, and the improvement was limited by memory throughput rather than compute throughput.

I also implemented a version with bank conflict avoidance by modifying shared memory layout. However, this kernel used a grid configuration that resulted in a very small grid size, which caused low GPU utilization. The profiler indicated that the grid was too small to fully utilize the GPU resources, and this resulted in lower occupancy and higher execution time even though the kernel had advanced optimizations.

Finally, I implemented an optimized kernel using vectorized memory loads (uchar4) and the read-only data cache using __ldg(). This improved global memory access efficiency and increased memory throughput and L2 cache throughput significantly. Profiling showed that this version had the lowest execution time and the highest memory and compute utilization among all kernels.

### Key Observations

* Global memory access is the main bottleneck in the naive implementation.
* Shared memory tiling significantly reduces global memory accesses and improves performance.
* Register blocking increases computation per thread and improves SM utilization.
* Removing boundary checks using padding reduces branch divergence.
* Loop unrolling reduces instruction overhead.
* Double buffering increases shared memory usage and does not always give large performance improvement.
* Grid size and launch configuration significantly affect GPU utilization.
* Vectorized memory access improves memory throughput and cache utilization.
* The best performance was achieved when memory access was optimized and computation per thread was increased.
