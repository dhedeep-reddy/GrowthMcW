1. GPU Fundamentals and Design Philosophy

I started by understanding why GPUs exist and how they differ from CPUs. CPUs are designed to minimize latency for a small number of complex tasks, while GPUs are designed to maximize throughput by executing a large number of operations in parallel. GPUs achieve this by using thousands of simpler compute units rather than a few powerful cores like CPUs.

The concepts of latency and throughput computing were studied. Latency refers to the time required to complete a single operation, while throughput refers to the number of operations that can be completed per unit time. GPUs focus on maximizing throughput by executing many operations simultaneously.

The concepts of SIMD (Single Instruction Multiple Data) and SIMT (Single Instruction Multiple Threads) were also studied. SIMD is commonly used in CPUs where one instruction operates on multiple data elements using vector instructions such as SSE and AVX. SIMT is the GPU equivalent where multiple threads execute the same instruction on different data elements.

Data parallelism was also examined. In data parallelism the same operation is applied to a large dataset simultaneously. This is the core principle behind GPU computing and is widely used in applications such as image processing, matrix multiplication, and machine learning workloads.

2. GPU Architecture Basics

Next, I studied the hardware components that make up a GPU. The main processing unit inside a GPU is the Streaming Multiprocessor (SM). A GPU consists of multiple SMs, and each SM contains several compute and memory components required for executing threads.

Important architectural components studied include:

Streaming Multiprocessor (SM) – The main compute unit responsible for executing threads.
CUDA cores – Arithmetic units responsible for general floating-point and integer operations.
Tensor cores – Specialized units designed to accelerate matrix multiplications used in AI and deep learning workloads.
RT cores – Specialized units used for ray tracing operations such as ray–triangle intersection and bounding volume hierarchy traversal.
Warp scheduler – Hardware responsible for selecting which warp of threads executes next in order to keep the compute units busy.
Registers – Fast per-thread storage used during computation.
Shared memory – On-chip memory shared between threads within a block.
Load/store units – Responsible for handling memory operations.

The execution hierarchy of GPU threads was also studied. Threads are organized in the following hierarchy:

Thread → Warp → Thread Block → Grid

A thread is the smallest execution unit. Threads are grouped into warps, where each warp contains 32 threads. Warps are grouped into thread blocks, and thread blocks are organized into a grid when launching a GPU kernel. Blocks are scheduled across different SMs in the GPU.
Warp execution was studied in detail. Threads in a warp execute the same instruction simultaneously. If threads in a warp follow different branches due to conditional statements, warp divergence occurs and the GPU executes the different branches sequentially, which reduces performance.
Occupancy was also studied. Occupancy refers to the number of active warps running on a Streaming Multiprocessor compared to the maximum number supported. Higher occupancy allows the GPU to hide memory latency more effectively by switching between warps.

3. GPU Memory Hierarchy

The memory hierarchy of GPUs was studied because memory access patterns significantly affect performance. GPU memory is organized in multiple levels, each with different latency and scope.

Registers – The fastest memory available on the GPU. Registers are private to each thread and have extremely low latency.

Shared memory – Fast on-chip memory accessible by all threads within a block. Shared memory is used to reduce the number of accesses to slower global memory.

Global memory – The main GPU memory (VRAM). It is accessible by all threads but has significantly higher latency compared to registers and shared memory.

Constant memory – A read-only cached memory region optimized for situations where multiple threads read the same value.

Texture memory – Specialized cached memory designed for spatial locality and commonly used in graphics and image processing operations.

Local memory – Memory used when register space is insufficient. Despite the name, local memory resides in global memory and therefore has higher latency.

L1 cache – A small cache located within each SM that reduces memory access latency.

L2 cache – A larger cache shared across all SMs in the GPU.

The approximate latency hierarchy studied was:

Registers (about 1 cycle)
Shared memory (around 20 cycles)
L1 cache (tens of cycles)
L2 cache (hundreds of cycles)
Global memory (hundreds of cycles)

The concept of memory bandwidth was also studied. Memory bandwidth represents the amount of data that can be transferred between the GPU and VRAM per second. It is measured in gigabytes per second (GB/s).

Memory latency refers to the delay between issuing a memory request and receiving the data. GPUs hide memory latency by scheduling multiple warps and switching execution to another warp while one warp waits for memory.

Memory coalescing was also studied. Coalescing occurs when threads in a warp access consecutive memory addresses, allowing the GPU to combine multiple memory requests into a single transaction. Poor memory access patterns lead to inefficient bandwidth usage.

4. GPU Programming Model

I then studied the GPU programming model used in CUDA, HIP, and OpenCL.

GPU programs are divided into two parts:

Host code – Code executed on the CPU.
Device code – Code executed on the GPU.

The CPU is responsible for allocating GPU memory, transferring data between host and device, launching kernels, and retrieving results.

A kernel is a function that runs on the GPU and is executed by many threads simultaneously. Each thread executes the same kernel code but operates on different portions of the data.

Kernel execution is launched from the CPU using the following structure:

CPU (Host)
Launch kernel
GPU executes threads in parallel

The hierarchy used when launching a kernel consists of grids, blocks, and threads. Blocks contain multiple threads, and grids contain multiple blocks. Blocks are scheduled onto Streaming Multiprocessors where threads are executed in warps.
Thread synchronization was also studied. Threads within the same block can synchronize using barrier instructions such as __syncthreads(), which ensures all threads reach a certain point before continuing execution. Blocks cannot directly synchronize with each other during kernel execution.

5. RTX 5060 Blackwell Architecture Study

I also studied the hardware specifications of the RTX 5060 GPU based on the Blackwell architecture to understand how the architectural concepts map to a real GPU.

The RTX 5060 uses the Blackwell GB206 chip and includes the following approximate hardware configuration:

Streaming Multiprocessors: 26
CUDA cores: 3840
Tensor cores: about 120 (5th generation)
RT cores: about 30 (4th generation)
VRAM: 8 GB GDDR7
Memory bus width: 128-bit
Memory bandwidth: about 448 GB/s

Each Streaming Multiprocessor contains CUDA cores, Tensor cores, RT cores, registers, shared memory, and warp scheduling hardware.

Warps consist of 32 threads. Each SM can support dozens of active warps simultaneously, allowing the GPU to execute tens of thousands of threads concurrently across the entire device.

6. Memory Bus and Bandwidth

I studied how the GPU memory bus and bandwidth determine memory transfer speed.

The memory bus refers to the physical connection between the GPU and VRAM. Its width determines how many bits can be transferred per cycle. The RTX 5060 uses a 128-bit memory bus.

Memory bandwidth depends on bus width and memory speed. For the RTX 5060, the effective bandwidth is approximately 448 GB/s, meaning the GPU can transfer roughly 448 gigabytes of data per second between the GPU and its VRAM.

This bandwidth is important for workloads that require frequent memory access, as insufficient bandwidth can cause compute units to wait for data.
