# CPU vs GPU Computing

The first concept I studied was the architectural difference between CPUs and GPUs.

CPUs are designed to optimize **low-latency sequential execution**, while GPUs are designed for **high-throughput parallel computation**.

A CPU typically contains a small number of powerful cores, whereas a GPU contains thousands of smaller compute units designed to execute many threads simultaneously.

CPU structure conceptually looks like:

```
CPU
 ├ Core 1
 ├ Core 2
 ├ Core 3
 └ Core 4
```

Each CPU core executes instructions independently and is optimized for complex control logic, branch prediction, and large cache systems.

A GPU on the other hand consists of many **Streaming Multiprocessors (SMs)** that execute thousands of lightweight threads.

```
GPU
 ├ SM 0
 ├ SM 1
 ├ SM 2
 ├ SM 3
```

Each SM contains many CUDA cores and runs many threads concurrently. The GPU architecture is designed for workloads where the same operation is applied to a large amount of data, such as vector operations, matrix multiplication, image processing, and deep learning workloads.

# GPU Architecture and Streaming Multiprocessors

The next concept studied was the internal structure of GPUs and the role of the Streaming Multiprocessor (SM).

An SM is the main compute unit of a GPU. Each SM contains multiple hardware components that enable parallel execution.

Typical components inside an SM include:

* CUDA cores
* Warp schedulers
* Registers
* Shared memory
* Load/store units
* Special function units

The structure can be visualized as:

```
Streaming Multiprocessor

 ├ Warp Scheduler
 ├ CUDA Cores
 ├ Registers
 ├ Shared Memory
 ├ Load/Store Units
 └ Special Function Units
```

CUDA cores perform arithmetic and logic operations. Registers store temporary values used by threads. Shared memory allows threads within a block to communicate and reuse data efficiently.

Blocks of threads are assigned to SMs by the CUDA scheduler and executed concurrently.

# Warps and Execution Model

Another important concept studied was **warp execution**.

Although CUDA programs are written in terms of threads, the GPU does not execute individual threads independently. Threads are executed in groups called **warps**.

A warp contains **32 threads**.

```
Warp
 ├ Thread 0
 ├ Thread 1
 ├ Thread 2
 ...
 └ Thread 31
```

All threads within a warp execute the same instruction at the same time. This execution model is called **SIMT (Single Instruction Multiple Threads)**.

Example of a parallel operation:

```
C[i] = A[i] + B[i]
```

Each thread processes one element:

```
Thread 0 → C[0] = A[0] + B[0]
Thread 1 → C[1] = A[1] + B[1]
Thread 2 → C[2] = A[2] + B[2]
```

Warps are scheduled by the SM. When one warp waits for memory access, another warp is executed. This mechanism is known as **latency hiding**.

# CUDA Thread Hierarchy

CUDA programs organize parallel execution using a hierarchy consisting of grids, blocks, and threads.

```
Grid
 └ Blocks
     └ Threads
```

Threads are grouped into blocks, and blocks are grouped into a grid.

Threads inside the same block can:

* communicate with each other
* synchronize execution
* share memory

Blocks are executed independently and can be scheduled on different SMs.

# CUDA Kernel Structure

CUDA programs contain two types of code:

Host code which runs on the CPU and device code which runs on the GPU.

GPU functions are called **kernels**.

Example CUDA kernel:

```cpp
__global__ void add(int *A, int *B, int *C, int N)
{
    int i = blockIdx.x * blockDim.x + threadIdx.x;

    if(i < N)
        C[i] = A[i] + B[i];
}
```

The `__global__` keyword indicates that the function is executed on the GPU and called from the CPU.

Each thread calculates its global index using the expression:

```
i = blockIdx.x * blockDim.x + threadIdx.x
```

This ensures that every thread processes a unique element.

---

# Kernel Launch Configuration

CUDA kernels are launched using the triple angle bracket syntax.

```
kernel<<<numBlocks, threadsPerBlock>>>();
```

Example:

```cpp
add<<<blocks, threads>>>(d_A, d_B, d_C, N);
```

If we choose:

```
threads = 256
blocks = 4
```

Then the total number of threads executing the kernel will be:

```
4 × 256 = 1024
```

These threads are distributed across SMs automatically by the CUDA runtime.

# GPU Memory Management

GPU memory must be allocated and managed explicitly.

Memory allocation on the GPU is done using `cudaMalloc`.

Example:

```cpp
int *d_A;
cudaMalloc(&d_A, N * sizeof(int));
```

Data must be copied between the CPU and GPU using `cudaMemcpy`.

Example:

```cpp
cudaMemcpy(d_A, h_A, N*sizeof(int), cudaMemcpyHostToDevice);
```

The four parameters specify:

* destination pointer
* source pointer
* size of data
* direction of copy

Data is copied back from the GPU to the CPU using:

```cpp
cudaMemcpy(h_C, d_C, N*sizeof(int), cudaMemcpyDeviceToHost);
```

After computation, GPU memory must be released using:

```cpp
cudaFree(d_A);
```

# First CUDA Program Practiced

A complete vector addition CUDA program was studied and practiced.

```cpp
__global__ void add(int *A, int *B, int *C, int N)
{
    int i = blockIdx.x * blockDim.x + threadIdx.x;

    if(i < N)
        C[i] = A[i] + B[i];
}
```

Host code initializes arrays and allocates GPU memory:

```cpp
int *d_A,*d_B,*d_C;

cudaMalloc(&d_A,size);
cudaMalloc(&d_B,size);
cudaMalloc(&d_C,size);
```

Input arrays are copied to the GPU:

```cpp
cudaMemcpy(d_A,h_A,size,cudaMemcpyHostToDevice);
cudaMemcpy(d_B,h_B,size,cudaMemcpyHostToDevice);
```

The kernel is then launched:

```cpp
int threads = 256;
int blocks = (N + threads - 1) / threads;

add<<<blocks,threads>>>(d_A,d_B,d_C,N);
```

Finally, results are copied back to the CPU:

```cpp
cudaMemcpy(h_C,d_C,size,cudaMemcpyDeviceToHost);
```

# CUDA Memory Hierarchy

Another important topic studied was the CUDA memory hierarchy.

Different memory types have different speeds and scopes.

```
Registers
Shared Memory
Global Memory
Constant Memory
Local Memory
```

Registers are the fastest memory and are private to each thread.

Shared memory is fast on-chip memory shared between threads in the same block.

Global memory is the main GPU memory and is accessible by all threads but has high latency.

Efficient CUDA programs minimize global memory access and reuse data through shared memory.

# Thread Synchronization

Threads within the same block can synchronize execution using:

```
__syncthreads()
```

Example:

```cpp
__shared__ int temp[256];

temp[threadIdx.x] = A[threadIdx.x];

__syncthreads();
```

This ensures that all threads finish writing to shared memory before any thread begins reading from it.

Synchronization is limited to threads within the same block.

---

# Memory Coalescing

Memory coalescing refers to combining multiple memory accesses from threads in a warp into fewer global memory transactions.

Efficient access pattern:

```
Thread 0 → A[0]
Thread 1 → A[1]
Thread 2 → A[2]
Thread 3 → A[3]
```

This produces contiguous memory access and allows the GPU to merge requests.

Inefficient pattern:

```
Thread 0 → A[0]
Thread 1 → A[32]
Thread 2 → A[64]
Thread 3 → A[96]
```

This forces the GPU to perform many separate memory transactions, reducing performance.

---

# Shared Memory Optimization

Shared memory optimization involves loading frequently reused data from global memory into shared memory so that multiple threads can reuse it.

Example declaration:

```cpp
__shared__ float tileA[16][16];
__shared__ float tileB[16][16];
```

Threads load tiles from global memory into shared memory and perform computation using the faster shared memory.

This technique is widely used in optimized matrix multiplication kernels.

---

# Occupancy

Occupancy represents how many warps are active on an SM compared to the maximum possible warps.

```
Occupancy = active warps / maximum warps
```

Factors that limit occupancy include:

* register usage per thread
* shared memory usage per block
* maximum threads per SM

Higher occupancy helps hide memory latency by ensuring there are always warps ready to execute.

---

# Warp Divergence

Warp divergence occurs when threads in a warp follow different execution paths.

Example:

```cpp
if(threadIdx.x % 2 == 0)
    do_A();
else
    do_B();
```

Threads in the same warp may execute different branches, causing the GPU to run the branches sequentially while some threads remain idle.

This reduces parallel efficiency and should be minimized when designing CUDA kernels.
